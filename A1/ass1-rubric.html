comp10002 Assignment 1 (2026) Marking Rubric and Feedback

Section A: Program Presentation

Including: layout and style, readability, adherence to coding expectations, general care and appearance. Stage allocations are cumulative.

Additions

  • Stage 1 initial allocation, +6.
  • Stage 2 initial allocation, +1.
  • Stage 3 initial allocation, +1.

Deductions

All stage deductions are cumulative. Marks in Section A won't go below zero.

  • use of magic numbers, –1;
  • #defines not in upper case, –1;
  • absence of function prototypes, –1;
  • inconsistent naming conventions, –1;
  • inconsistent bracket placement, –1;
  • inconsistent indentation, –1;
  • excessive commenting, –1;
  • insufficient commenting, –1;
  • lack of whitespace (visual appeal), –1;
  • lines >80 chars, –1;
  • excessive whitespace, –1;
  • unhelpful #defines, –1;
  • constant two-dimensional array subscripts, –1;
  • typedef names without a _t suffix, –1;

Bonus additions (included in total mark only if there were marks deducted within Section A)

  • comment that says "algorithms are fun", +1;

Section B: Structure and Approach

Including: decomposition in to functions, development of data structures and declaration of them at the appropriate locations, choice of parameters to functions, overall flow and high-level readability. Stage allocations are cumulative.

Additions

  • Stage 1 initial allocation, +4.
  • Stage 2 initial allocation, +1.
  • Stage 3 initial allocation, +1.

Deductions

All stage deductions are cumulative. Marks in Section B won't go below zero.

  • duplicate code segments, –1;
  • main program too long or too complex, –1;
  • functions too long or too complex, –1;
  • global variables, –1;
  • insufficient use of functions, –1;
  • overly complex function argument lists, –1;
  • avoidance of typedefs, –1;
  • unnecessary copying of structured data, –1;

Section C: Program Execution

Including: compilation, execution on test data, output presentation and readability. Programs that do not compile in the test environment will lose all marks in this section. Be sure to check the GradeScope execution output before you say "finished" to yourself. Stage allocations are cumulative.

Additions

  • Stage 1 initial allocation, +2.
  • Stage 2 initial allocation, +2.
  • Stage 3 initial allocation, +2.

Deductions

  • programs that fail to compile will be marked as Stage 1 submissions;
  • programs that segfault will be marked based on the output that is generated;
  • programs that generate no or trivial output will receive zero on this section;
  • unnecessary warning messages in compilation, –1;
  • whitespace mismatch in any output line in any test case, –1;
  • text/punctuation mismatch in any output line in any test case, –1;
  • small numeric mismatch (rounding, or digits of precision) in any output line in any test case, –1;
  • large calculation error in any output line in any test case, –1;
  • additional output lines generated, –1;
  • missing output lines, –1;

All stage deductions are cumulative. Marks in Section C won't go below zero.

Section D: Late Penalty

If you make a late submission without having prior agreement from Alistair, a late penalty will be applied. Overall marks won't go below zero. No assignments -- with or without late penalty -- will be accepted more than seven calendar days after the assignment deadline.

  • one calendar day late, –2;
  • two calendar days late, –4;
  • three calendar days late, –6;
  • four calendar days late, –8;
  • five to seven days late, –10;

Marks in Section D will subtract from the sum of the marks obtained in Sections A, B, and C.

Section E: Authorship Declaration

The following deduction will be applied to your overall mark if necessary. Overall marks won't go below zero.

  • missing (or empty) Authorship Declaration at top of program, –5;

Marks in Section E will subtract from the sum of the marks obtained in Sections A, B, and C, and add to any deductions incurred in Section D.

Overall marks won't go below zero.
